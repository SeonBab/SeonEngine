# 코드 컨벤션

이 문서는 현재 합의한 엔진 코드 규칙을 정리합니다. 항목은 필요할 때 추가합니다.

## 서식

- 들여쓰기에 탭을 사용하고, 탭 표시 폭은 4칸으로 설정합니다.
- 여는 중괄호는 다음 줄에 둡니다(Allman 스타일). 다만 아래의 한 줄 조기 종료와 getter는 예외로 허용합니다.
- `if`, `while` 등 제어문의 본문에는 중괄호를 사용합니다.
- `else`가 없고 본문이 `return`, `continue`, `break` 중 한 문장뿐인 `if`는 한 줄로 쓸 수 있습니다. 예: `if (!isValid) { return false; }`.
- 클래스 안에서 정의하는 getter 중 본문이 `return` 한 문장뿐인 경우 한 줄로 쓸 수 있습니다. 예: `int GetWidth() const { return width; }`. setter와 그 외 함수에는 적용하지 않습니다.

## 이름

- 타입과 열거형 값에는 PascalCase를 사용합니다. 타입 종류를 나타내는 접두사는 사용하지 않습니다. 예: `WindowsApplication`, `WindowState::Minimized`.
- 함수와 메서드에는 PascalCase를 사용합니다. 예: `Initialize`, `Create`.
- 지역 변수, 매개변수와 멤버 변수에는 camelCase를 사용합니다. 멤버 변수에 별도 접두사는 붙이지 않습니다. 예: `instance`, `window`.
- 매개변수는 멤버 변수와 다른 이름을 사용하고 값의 역할을 드러냅니다. 예: 멤버 `width`에 설정할 값은 `newWidth`로 씁니다.
- `bool` 변수에는 `b` 접두사를 붙이지 않고 의미가 드러나는 이름을 사용합니다. 예: `isVisible`, `hasFocus`. `bool` 반환 함수도 함수의 PascalCase 규칙을 따릅니다. 예: `IsVisible()`, `HasFocus()`.
- 약어는 대문자를 유지합니다. camelCase 이름이 약어로 시작하면 첫 약어 전체를 소문자로 씁니다. 예: `GPUBuffer`, `textureID`, `gpuBuffer`. 외부 API 이름은 원래 표기를 유지합니다.
- 고정된 의미를 가진 이름 붙인 상수에는 PascalCase를 사용합니다. 예: `WindowClassName`. 일반 지역 변수는 변경을 막기 위해 `const`를 붙여도 camelCase를 사용합니다. 예: `windowWidth`.

## 주석

- 주석은 한국어를 기본으로 쓰고 API 이름과 코드 식별자는 원래 표기를 유지합니다.
- 코드만으로 알기 어려운 이유, 제약, 주의사항과 사용 계약을 설명합니다. 코드 내용을 그대로 반복하는 주석은 쓰지 않습니다.
- 함수나 변수의 실패 조건, 단위, 좌표계, 수명과 소유 관계, 사용 순서 등 필요한 의미가 이름과 타입만으로 충분히 드러나지 않으면 주석을 답니다.
- 사용에 필요한 계약은 선언이나 관련 처리 코드 옆에 둡니다. 모든 변수나 함수에 기계적으로 주석을 달지는 않습니다.
- 함수 선언의 설명은 `/** ... */`로 작성합니다. 짧은 설명은 한 줄로 쓸 수 있습니다. 함수 구현 안의 설명은 `//`를 사용합니다.
- 미완료 작업은 `TODO: 내용` 형식으로 표시합니다. 예: `// TODO: 창 생성 실패 로그를 남긴다.`

## const와 constexpr

- 객체 상태를 바꾸지 않는 멤버 함수에는 `const`를 붙입니다.
- 변경하지 않는 지역 변수에는 `const`를 붙이는 것을 권장하되 강제하지 않습니다.
- 컴파일 시점에 정해져야 하는 상수에는 `constexpr`을 사용합니다. 실행 중에 얻는 값을 변경하지 않을 때는 `const`를 사용할 수 있습니다.

## 멤버 기본값

- 공통 기본값이 있는 멤버는 선언부에서 초기화합니다.

## 가상 함수

- 부모 클래스의 가상 함수를 재정의할 때 `override`를 붙입니다.
- 부모 타입을 통해 자식 객체를 삭제할 수 있도록 공개하는 클래스는 가상 소멸자를 둡니다.

## 타입 별칭

- 새로 작성하는 타입 별칭은 `using`으로 선언합니다. 예: `using WindowID = unsigned int;`.

## 타입 추론

- 변수의 타입은 명시하는 것을 기본으로 하고 `auto`는 가급적 사용하지 않습니다.
- 람다를 변수에 담거나 구조적 바인딩을 사용할 때는 `auto`를 허용합니다.
- 반복자나 템플릿 코드에서 타입을 명시하기 어렵거나 지나치게 길어 읽기 힘들 때도 `auto`를 허용합니다.

## 형 변환

- 명시적 형 변환에는 C 스타일 캐스트 대신 의도에 맞는 C++ 캐스트를 사용합니다. 예: `static_cast<int>(value)`.

## 열거형

- 새로 정의하는 열거형은 `enum class`를 기본으로 사용합니다. 외부 API가 제공하는 열거형은 해당 선언을 그대로 사용합니다.

## 실패 전달

- 호출자가 성공과 실패만 구분하면 충분한 함수는 `bool`을 반환할 수 있습니다. 호출자가 원인별로 다르게 처리해야 할 때는 필요한 오류 정보를 전달합니다.

## 파일과 헤더

- C++ 헤더에는 `.h`, 소스에는 `.cpp` 확장자를 사용합니다.
- 주된 타입이 있는 파일은 그 타입의 이름을 사용합니다. 예: `WindowsApplication.h`. 주된 타입이 없는 파일은 역할을 나타내는 이름을 사용합니다. 예: `EngineMain.cpp`.
- 헤더의 중복 포함 방지에는 `#pragma once`를 사용합니다.
- 헤더에서는 `using namespace`를 사용하지 않습니다. 예를 들어 표준 라이브러리 이름은 `std::vector`처럼 명시합니다. `using`을 사용한 타입 별칭은 이 규칙의 대상이 아닙니다.
- `.cpp`에서도 `using namespace std;`를 사용하지 않고 `std::`를 명시합니다.
- `.cpp`에서는 대응하는 자신의 헤더를 먼저 포함합니다. 그다음 엔진 헤더, 외부 라이브러리 헤더, C++ 표준 라이브러리 헤더 순서로 묶습니다. 그룹 사이에는 빈 줄을 두고 각 그룹은 이름순으로 정렬합니다.
- 파일에서 직접 사용하는 선언은 해당 파일에서 직접 포함하거나, 아래 조건에 맞게 전방 선언합니다. 다른 헤더가 간접적으로 포함하는 것에 의존하지 않습니다.
- 헤더에서 포인터나 참조로만 사용하는 타입은 전방 선언할 수 있습니다. 값 멤버나 부모 클래스처럼 전체 정의가 필요한 경우에는 해당 헤더를 직접 포함합니다.
